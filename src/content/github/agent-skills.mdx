## 项目介绍

Agent Skills 是 Addy Osmani 维护的一套 **面向 AI 编码代理的生产级工程技能包**。它把资深工程师在规格、实现、测试、审查与上线中的工作流、质量门禁与反合理化表，封装成 24 项可触发技能与 8 条斜杠命令（`/spec` → `/ship`），让 Claude Code、Cursor、Codex 等宿主在全生命周期中一致地执行这些实践，而不是默认走「最短路径、跳过验证」的捷径。技能设计吸收了 *Software Engineering at Google* 与 Google 工程实践中的概念（如 Hyrum's Law、Beyonce Rule、Chesterton's Fence、Shift Left）。

## 核心特性

- **生命周期斜杠命令**：`/spec`、`/plan`、`/build`、`/test`、`/review`、`/webperf`、`/code-simplify`、`/ship` 映射「定义 → 计划 → 构建 → 验证 → 审查 → 上线」；`/build auto` 可在一次计划审批后自主推进任务（失败或高风险步骤仍会暂停）
- **24 项结构化技能**：含 `interview-me`、`spec-driven-development`、`test-driven-development`、`code-review-and-quality`、`security-and-hardening` 等，每项含步骤、验证门禁与 anti-rationalization 表
- **情境自动激活**：设计 API 触发 `api-and-interface-design`，构建 UI 触发 `frontend-ui-engineering` 等，无需每次手动指定
- **专家 Persona**：`code-reviewer`、`test-engineer`、`security-auditor`、`web-performance-auditor` 用于定向审查
- **跨宿主安装**：skills CLI、Claude Code / Codex 插件、Cursor、Gemini CLI、Antigravity、OpenCode、Copilot 等均有官方文档路径

## 对用户价值

编码代理默认倾向最短路径——跳过规格、测试、安全审查与可观测性，产出的往往是原型质量而非生产质量。Agent Skills 把「何时写规格、测什么、如何审查、何时上线」写成可执行工作流：先对齐需求与 PRD，再小步实现与 TDD，合并前走五轴审查与安全加固，上线前有清单与回滚意识。适合希望 Agent 像资深工程师一样守纪律、而不是只会快速堆代码的个人与团队。

## 与替代方案

- 相比 [Superpowers](https://github.com/obra/superpowers)：官方 [comparison](https://github.com/addyosmani/agent-skills/blob/main/docs/comparison.md) 指出两者同属全生命周期方法论包；Agent Skills 更强调 Google 工程实践嵌入、Web 性能（`/webperf`）与上线/弃用等「Ship」侧技能，Superpowers 更突出 brainstorming、子代理编排与 git worktree 收尾。
- 相比 [Matt Pocock skills](https://github.com/mattpocock/skills)：后者刻意做小而可组合、可本地改写的技能，反对方法论「拥有」整条流程；本仓库是意见鲜明的完整研发包，适合想开箱即用整套门禁的人。
- 相比 [Karpathy Coding Guidelines](https://github.com/multica-ai/andrej-karpathy-skills) 等单文件行为准则：本仓库提供可触发命令与技能链，而不只是编码克制原则。
- 若你只需要官方 Skills 规范与跨宿主分发标准，可并行参考 [agentskills.io](https://agentskills.io)；本仓库是方法论实践集，不是规范本身。

## 适应人群

- 使用 Claude Code、Cursor、Codex 等工具，希望 Agent 先规格再写码、先验证再声称完成的工程师。
- 需要把规格、TDD、五轴审查、安全与上线清单统一进团队 AI 工作流的 Tech Lead。
- 做 Web / 前端产品、关心 Core Web Vitals 与可访问性门禁，希望 `/webperf` 与前端技能开箱可用的开发者。

## 如何使用

### 前置条件

- 已安装可运行 Agent Skills 的宿主（Claude Code、Cursor、Codex、Gemini CLI 等；skills CLI 声称支持 70+ agents）。
- 使用 skills CLI 时需 Node.js / `npx`；Claude Code / Codex 插件路径需对应 CLI。
- 了解整仓安装与单技能安装的差异：单技能 `npx` 安装不会复制仓库级 `references/` 清单（见 issue [#361](https://github.com/addyosmani/agent-skills/issues/361)）。

### 安装方式

**方式 A：skills CLI（跨宿主最快路径）**

```bash
npx skills add addyosmani/agent-skills            # 安装全部 24 项技能
npx skills add addyosmani/agent-skills --list      # 先浏览再安装
npx skills add addyosmani/agent-skills --skill test-driven-development
```

**方式 B：Claude Code 插件**

```
/plugin marketplace add addyosmani/agent-skills
/plugin install agent-skills@addy-agent-skills
```

若 marketplace 走 SSH 报错，可用 HTTPS：

```
/plugin marketplace add https://github.com/addyosmani/agent-skills.git
```

**方式 C：Codex 插件（CLI v0.122+）**

```bash
codex plugin marketplace add addyosmani/agent-skills
codex plugin add agent-skills@agent-skills
```

Cursor、Antigravity、Gemini CLI 等见仓库 `docs/` 下对应 setup 文档，或站点 [skills.addy.ie](https://skills.addy.ie)。

### 首次运行

安装后在目标仓库打开 Agent 会话。建议先跑 `/spec` 或直接调用 `interview-me` / `spec-driven-development` 对齐需求，再 `/plan` → `/build`（或 `/build auto`）推进实现；需要合并前用 `/review`，性能相关用 `/webperf`。

### 验证是否成功

- 斜杠菜单或技能列表中能看到本包命令 / 技能（如 `/spec`、`spec-driven-development`）。
- 发起中等复杂度任务时，代理应按技能步骤产出规格/计划、附带验证证据，而不是直接大段写代码。
- Claude Code / Codex：确认插件已启用且技能可被 `@` 或斜杠调用。

### 常见坑 / 注意事项

- **单技能安装缺 references**：只装个别 skill 时，共享 checklist 路径可能不可用；需要整仓集成、clone，或把所需清单拷进已安装 skill 的 `references/`。
- **SSH / marketplace**：Claude Code marketplace 默认 SSH；无 GitHub SSH key 时改用 HTTPS marketplace URL，或配置 `url."https://github.com/".insteadOf git@github.com:`（会影响本机全局 git URL 改写，按需使用）。
- **Cursor**：工作流技能放 `.cursor/skills/`，短策略放 `.cursor/rules/*.mdc`，不要把整份 skill 粘进 rules（见 `docs/cursor-setup.md`）。
- 存量代码库建议按官方 [Adoption Guide](https://github.com/addyosmani/agent-skills/blob/main/docs/adoption-guide.md) 做增量、验证优先 rollout，不必第一天就全生命周期强制启用。
