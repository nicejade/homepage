## 项目介绍

Immich 是一款高性能的自托管照片与视频管理系统，目标是在自有服务器上复刻 Google Photos 一类云相册的体验。官方提供 Web 与移动端 App：可后台自动备份、去重上传，并用人脸聚类、物体识别与 CLIP 语义搜索整理海量媒体。数据与元数据留在你控制的机器上，适合家庭与小团队长期归档。

## 核心特性

- 移动端自动备份（打开 App 或后台上传）、选择性相册备份，并避免重复资源
- 多用户、相册共享、公开分享与伴侣共享；支持 OAuth 与 API Key
- 基于元数据、人脸、物体与 CLIP 的搜索；地图视图与「X 年前今日」回忆
- 支持 RAW、Live Photo / Motion Photo、360° 图片（Web）与用户自定义存储结构
- 官方 Docker Compose 一键部署；另有公开 [Demo](https://demo.immich.app)（`demo@immich.app` / `demo`）

## 对用户价值

手机相册越堆越大，公有云空间贵、隐私边界不清，本地文件夹又难检索、难多端同步。Immich 把「自动备份 → 智能整理 → 多端浏览 → 分享协作」收成一套自托管闭环：照片仍在自家 NAS/VPS，却能像云相册一样按人、地、物快速找回。对已有 Homelab 的用户，这是摆脱订阅制相册最成熟的开源路径之一。

## 与替代方案

- 相比 **Google Photos / iCloud / OneDrive**：交互成熟但数据在厂商侧；Immich 隐私可控，代价是自行运维存储、备份与升级。
- 相比 **PhotoPrism / LibrePhotos**：同属自托管智能相册；Immich 在移动端自动备份、产品完成度与社区活跃度上通常更受 Homelab 用户青睐。
- 相比 **Nextcloud Photos / Seafile**：后两者偏通用网盘/同步，相册体验与人脸检索不是主战场；Immich 专攻媒体库与手机备份。
- 边界：Immich **不是备份方案本身**——官方反复强调必须遵循 [3-2-1](https://www.backblaze.com/blog/the-3-2-1-backup-strategy/)；若只要网盘同步而不需要相册智能功能，Nextcloud 等更合适。

## 适应人群

- 想替代 Google Photos / iCloud，把家庭照片与视频留在自有硬件上的个人用户。
- 已有 NAS、Homelab 或 Linux VPS，希望用 Docker 跑一套多用户私有相册的人。
- 需要人脸聚类、语义搜索与移动端自动备份，而不只是「文件夹挂网页」的归档需求者。

## 如何使用

### 前置条件

- 推荐 **Linux 64 位**（Ubuntu / Debian 等）；Windows / macOS 仅建议用 Docker Desktop / WSL2，官方协助能力有限。
- 硬件：建议 ≥ **6GB RAM**、**4 核 CPU**（最低约 2 核 / 4GB，低内存需关闭机器学习功能）；架构 `amd64` / `arm64`（自 v3 起 amd64 需支持 x86-64-v2）。
- 已安装 **Docker Engine + Compose 插件**（命令为 `docker compose`，不是已弃用的 `docker-compose`）。
- Postgres 数据目录（`DB_DATA_LOCATION`）应落在本地 SSD，**不要**放在网络共享盘；缩略图与转码大约额外占用库容量的 10–20%。
- 许可证为 AGPL-3.0；生产环境请改强随机 `DB_PASSWORD`，并限制公网裸暴露。

### 安装方式

官方推荐 Docker Compose（[安装文档](https://docs.immich.app/install/docker-compose)）：

```bash
mkdir ./immich-app && cd ./immich-app
wget -O docker-compose.yml https://github.com/immich-app/immich/releases/latest/download/docker-compose.yml
wget -O .env https://github.com/immich-app/immich/releases/latest/download/example.env
```

编辑 `.env`：设置 `UPLOAD_LOCATION`（媒体库路径）、`DB_DATA_LOCATION`、随机 `DB_PASSWORD`（建议仅 `A-Za-z0-9`），并按需取消注释 `TZ=`。

```bash
docker compose up -d
```

也可先在浏览器打开 [Demo](https://demo.immich.app) 体验；移动端把 Server Endpoint 设为 `https://demo.immich.app`。

### 首次运行

容器启动后，浏览器访问本机 Immich Web（默认端口见 compose / 文档），完成管理员注册。在手机 App 中填入服务器地址并登录，开启自动备份或选择相册上传几张测试照片。可选在管理界面检查机器学习与人脸识别是否正常排队处理。

### 验证是否成功

- Web UI 可登录，时间线出现刚上传的照片/视频。
- 移动端连接同一服务器后，备份任务能完成且无重复上传。
- 人脸/搜索（若启用 ML）对已入库资源可返回结果；`docker compose` 重启后历史库仍在。

### 常见坑 / 注意事项

- **Immich 不能替代备份**：务必对原始库与数据库做 3-2-1 备份；把 Immich 当唯一副本风险极高。
- 使用发行版自带的旧 Docker / `docker-compose` 会报错；请按官方指引安装 Docker 官方仓库版本。
- Windows 上 `DB_DATA_LOCATION` 不能落在 NTFS/FAT 或 WSL 挂载的 `/mnt/...`；可改为 Docker named volume。
- 升级前阅读官方升级说明与 Releases；生产环境建议锁定具体 `IMMICH_VERSION`，而不是盲目追 `latest`。
- 公网访问请置于反向代理 + HTTPS 之后，并评估 OAuth / 强密码等加固措施。
