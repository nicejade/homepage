## 项目介绍

Skills For Real Engineers 是 Total TypeScript / AI Hero 作者 Matt Pocock 从个人 `.agents` 目录公开的一套 **面向真实工程的 Agent Skills**。它刻意做成小、可组合、易本地改写的技能单元，而不是像 GSD、BMAD、Spec-Kit 那样「拥有」整条研发流程。技能面向任意模型与主流编码代理，把几十年工程经验压缩成可重复实践，目标是正经交付应用，而不是 vibe coding。

## 核心特性

- **`/grill-me` / `/grill-with-docs`**：上线前用拷问式访谈对齐意图；后者还会共建领域语言、更新 `CONTEXT.md` 与 ADR
- **工程闭环技能**：`/tdd`（红绿重构）、`/diagnosing-bugs`（分阶段诊断）、`/to-spec` / `/to-tickets` / `/implement`、`/code-review`（Standards × Spec 双轴）
- **架构与地图**：`/improve-codebase-architecture` 扫描「加深模块」机会并输出 HTML 报告；`/wayfinder` 把超大任务拆成可逐个决议的决策票
- **用户调用 vs 模型调用**：编排类技能仅人工触发；纪律类技能可被代理在合适场景自动拉起
- **双安装哲学**：Claude Code 官方 marketplace 插件（只读订阅、自动更新）或 [skills.sh](https://skills.sh/mattpocock/skills) / `npx skills`（拷贝可编辑文件，自主改写）

## 对用户价值

编码代理最常见的失败不是「写得慢」，而是意图错位、术语冗长、缺少反馈回路，以及在加速编码的同时加速代码腐化。这套技能用 grilling 缩小沟通鸿沟，用共享领域语言压低 token 与噪音，用 TDD / 诊断循环给代理可观测反馈，并用架构加深与 tracer-bullet 工单把大改动切成可控切片——同时把控制权留在你手里，方便按仓库改技能本身。

## 与替代方案

- 相比 [Agent Skills](https://github.com/addyosmani/agent-skills)：后者是意见鲜明的完整生命周期门禁包（规格 → 上线）；本仓库强调**小而可改、可组合**，反对方法论接管流程。
- 相比 [Superpowers](https://github.com/obra/superpowers)：Superpowers 更突出 brainstorming、子代理编排与 git worktree 收尾；本仓库更突出 grilling、领域模型/`CONTEXT.md`、以及「订阅插件 vs 可编辑拷贝」两种安装哲学。
- 相比 GSD / BMAD / Spec-Kit 一类「流程所有权」方案：它们帮你扛流程，但出 bug 时难拆；本仓库刻意不做总控，让你本地 hack。
- 相比 [Karpathy Coding Guidelines](https://github.com/multica-ai/andrej-karpathy-skills) 等单文件行为准则：这里提供可触发的斜杠技能链，而不只是编码克制原则。

## 适应人群

- 使用 Claude Code、Codex、Cursor 等工具，希望先对齐再动手、又不愿被整套方法论锁死的工程师。
- 需要在仓库里沉淀 `CONTEXT.md`、ADR 与可复用领域语言，降低代理废话与命名漂移的个人 / 小团队。
- 愿意把技能当「可 fork 的实践库」本地改写，而不是只订阅黑盒流程的资深开发者。

## 如何使用

### 前置条件

- 已安装 Claude Code，或其他支持 Agent Skills 的宿主（Codex、Cursor 等；`npx skills` 路径需 Node.js）。
- **二选一安装哲学**：插件（托管只读、随作者更新）或 skills.sh 拷贝（可编辑、自行 `npx skills update`）。**不要两种都装**，否则每个技能会出现两份。
- 使用工程向技能前，每个仓库先跑一次 `/setup-matt-pocock-skills`。

### 安装方式

**方式 A：Claude Code 插件（官方 marketplace，推荐「订阅」用法）**

```bash
claude plugins install mattpocock-skills
```

或在会话内：

```
/plugin install mattpocock-skills
```

无需先加 marketplace，更新随作者发布自动到达。

**方式 B：skills.sh / `npx skills`（可编辑拷贝，含 Codex 及其他宿主）**

```bash
npx skills@latest add mattpocock/skills
```

安装器会让你选择技能与目标宿主。**务必把 `setup-matt-pocock-skills` 选上。** 想自己改技能时也用同一命令；需要同步上游时：

```bash
npx skills update
```

### 首次运行

在目标仓库的 Agent 会话中执行一次 `/setup-matt-pocock-skills`：选择 issue tracker（GitHub / Linear / 本地文件）、triage 标签、以及文档落盘位置。之后日常改动建议先 `/grill-me` 或 `/grill-with-docs` 对齐，再视情况 `/to-spec` → `/to-tickets` → `/implement`（或直接 `/tdd`）。不确定用哪条技能时，可先 `/ask-matt`。

### 验证是否成功

- 斜杠菜单或技能列表中能看到本包命令（至少 `/setup-matt-pocock-skills`、`/grill-me`）。
- setup 完成后，后续 triage / 文档类技能应按你配置的 tracker 与目录工作。
- 发起一次中等复杂度改动：代理应先拷问澄清，而不是直接大段写代码；启用 `/grill-with-docs` 时仓库中应出现或更新 `CONTEXT.md` / ADR。

### 常见坑 / 注意事项

- **插件与 skills.sh 不要双装**：README 明确警告会得到两套重复技能。
- **漏装 `setup-matt-pocock-skills`**：工程技能依赖仓库级配置（tracker、标签、文档路径）；`npx skills` 安装时请主动勾选。
- **`/improve-codebase-architecture` 是勘察不是拯救**：老仓库能找出加深候选，但不会替你拆泥球。
- 原生 Codex 插件仍在路线图上；当前 Codex 等宿主以 `npx skills@latest add mattpocock/skills` 为准。
