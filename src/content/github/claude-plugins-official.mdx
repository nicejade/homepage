## 项目介绍

这是 Anthropic 维护的 **Claude Code 官方插件目录**：`.claude-plugin/marketplace.json` 是实际分发清单（约 290 个条目），覆盖开发、数据库、生产力、安全、监控等分类。仓库内 `/plugins` 放 Anthropic 自研插件，`/external_plugins` 放合作伙伴与社区提交；其余大量条目以 git 子目录或远程仓库形式挂进市场。每个插件可携带 Slash 命令、Agent、Skills、MCP 配置等，是扩展 Claude Code 的官方入口，而不是又一份技能合集。

## 核心特性

- **官方市场源**：Claude Code 内置 `@claude-plugins-official` 命名空间；`/plugin install {name}@claude-plugins-official` 或 `/plugin > Discover` 即可安装
- **双轨来源**：内部插件含 code-review、feature-dev、security-guidance、hookify、plugin-dev、skill-creator 及多语言 LSP；外部目录含 GitHub、Playwright、Linear、Firebase、Context7 等
- **标准插件结构**：必填 `.claude-plugin/plugin.json`，可选 `commands/`、`agents/`、`skills/`、`.mcp.json`
- **Skill-bundle**：远端仓库只有 `SKILL.md`、没有完整 manifest 时，可用 `strict: false` 加 `skills` 数组从 Git 子目录拉取
- **不可变 slug**：市场上架后 `name` 不得改名，否则已安装用户会遇到 `plugin-not-found`；展示名用 `displayName`，必要时走顶层 `renames` 映射迁移

## 对用户价值

自行拼装 MCP、Skills 与斜杠命令成本高、难版本化。官方目录把常用能力收成可安装、可审查的插件单元，降低「从零配置 Claude Code 扩展」的门槛。内部插件代表 Anthropic 推荐实践（代码审查、功能开发、安全指引、会话报告）；市场其余条目则把 GitHub、Linear、Playwright、云厂商工具接到终端 Agent 里。需要上架时走官方提交表，不必自建 marketplace JSON。

## 与替代方案

- 相比 [claude-code](https://github.com/anthropics/claude-code) 仓库内嵌的 `plugins/`：本仓库是 **独立、可扩展的官方市场源**，并包含第三方合作伙伴插件。
- 相比 [anthropics/skills](https://github.com/anthropics/skills)：后者以 `SKILL.md` 技能包为主；本目录覆盖完整插件形态（命令、Agent、MCP、LSP），也可挂 Skill-bundle。
- 相比 [awesome-agent-skills](https://github.com/VoltAgent/awesome-agent-skills) 等社区精选列表：那边跨宿主、偏浏览与拷贝安装；这里是 Claude Code 内置市场，安装与更新走 `/plugin`。
- 相比自建 marketplace 或只写 `.mcp.json`：官方源提供统一发现入口与命名空间，但插件内容由各作者维护。只要单一 MCP 时，直接配 `.mcp.json` 更轻。

## 适应人群

- 已使用 Claude Code，希望快速安装代码审查、LSP、MCP 等官方推荐扩展的开发者。
- 需要把 GitHub、Linear、Playwright 等第三方服务接入终端 Agent 工作流的工程师。
- 计划向官方市场上架插件的合作伙伴，或对照 `example-plugin` / `plugin-dev` 学习结构的维护者。

## 如何使用

### 前置条件

- 已安装并可正常启动 [Claude Code](https://github.com/anthropics/claude-code) CLI。
- 官方市场通常已自动注册；若 Discover 里看不到，再执行 `/plugin marketplace add anthropics/claude-plugins-official`。
- 阅读免责声明：Anthropic 不控制插件内 MCP 服务器与外部软件行为，安装前确认来源可信。
- 查阅各插件 `README.md` 了解额外依赖（语言运行时、API 密钥）。

### 安装方式

在 Claude Code 会话中安装指定插件（将 `{plugin-name}` 换成目录名，如 `code-review`）：

```
/plugin install {plugin-name}@claude-plugins-official
```

或打开 **`/plugin > Discover`** 浏览官方市场并选择安装。

浏览清单可克隆本仓库查看 `plugins/`、`external_plugins/` 与 `.claude-plugin/marketplace.json`，或参阅 [官方插件文档](https://code.claude.com/docs/en/plugins)。合作伙伴上架走 [插件目录提交表单](https://clau.de/plugin-directory-submission)。

### 首次运行

建议先在测试项目里只装一个插件，例如：

```
/plugin install code-review@claude-plugins-official
```

再按插件类型试对应入口：Slash 命令（如 `/code-review`）、自动触发的 Agent / Skills，或 README 中的 MCP 能力。确认行为符合预期后再纳入日常流程。

### 验证是否成功

在 `/plugin` 列表中应能看到已安装的 `@claude-plugins-official` 插件。执行该插件文档中的示例命令或触发语，确认无配置错误；若依赖 MCP，检查所需环境变量与网络可达性。

### 常见坑 / 注意事项

- **信任边界**：外部插件可能包含任意 MCP 服务器与脚本。Anthropic 做基础筛查，「Anthropic Verified」会多一层质量与安全审核，但仍无法保证行为不变。生产仓库安装前请读 homepage 与许可。
- **许可证分散**：仓库根目录为 Apache-2.0，各链接插件可能有独立 LICENSE，商用前需逐插件核对。
- **不要改已上架的 `name`**：只改 `displayName`；必须改 slug 时在 marketplace.json 的 `renames` 里做旧名映射，否则用户同步后会 `plugin-not-found`。
- **Skill-bundle** 需正确配置 `source`（git-subdir、ref、sha）与 `skills` 路径，否则无法加载远程 `SKILL.md`。
- 自研插件可参考 `plugins/example-plugin` 与 [plugin-dev](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/plugin-dev)；不一定要从本市场分发。
